Interface:

### crdkit.dictMerge

- Scope: public
- File: `_model.tpl`
- Called by: —
- Calls: [crdkit.ensureDictKey](#crdkit.ensureDictKey)
- Mutated arguments: `0`
- Writes ctx: —
- Reads ctx: —

Merges "value" into the dict at a path of $model, creating missing
levels as empty dicts (incoming keys win on collision).

Interface:
- Params (list): [model, key1, ..., keyN, value] (N >= 0)
  - model: root dict to walk from
  - key1..keyN: path (may be empty)
  - value: dict to merge in at the end of the path
- Returns: nothing (mutates $model in place).

Implementation notes:
- List-based (dig-style, variadic path) rather than dict-with-named-
  keys — mirrors Sprig's `dig`, but reversed arg order (`dig` reads, so
  the target dict is last there too, but the source it reads FROM is
  last; this WRITES, so the root it's anchored to is first).
- Zero path keys (`[model, value]`) is a supported degenerate case:
  merges "value" directly into "model", no nesting — for setting
  several independent top-level scalar fields in one shot (e.g.
  apiVersion/kind). Requires at least `[model, value]` (2 elements);
  fewer is a template-authoring bug (ordinary template error, not a
  diagnostic).

### crdkit.ensureDictKey

- Scope: public
- File: `_model.tpl`
- Called by: [crdkit.dictMerge](#crdkit.dictMerge), [crdkit.listExtend](#crdkit.listExtend)
- Calls: —
- Mutated arguments: `model`
- Writes ctx: —
- Reads ctx: —

Ensures $model has "key" set, initializing it to "default" if absent.

Interface:
- Params (dict): { "model": <live model dict>, "key": <string>,
  "default": <zero value, e.g. (list) or (dict)> }
- Returns: nothing (mutates $model in place).

Implementation notes:
- Maps are reference types: a map passed as an include argument, even
  nested inside a wrapping dict literal, is still the SAME underlying
  map the caller holds — a `set` here is visible to the caller once
  this include returns.
- This is what lets any integration touch a ctx.model field without a
  central, pre-declared "model shape" — no field is pre-initialized.
- For "field is a map, add entries" or "field is a list, add items" a
  merge/extension helper fits better; reach for this only for a shape
  neither covers.

### crdkit.integrations.chain

- Scope: public
- File: `_chain.tpl`
- Called by: [crdkit.render](#crdkit.render)
- Calls: [crdkit.snapshotCtx.internal](#crdkit.snapshotCtx.internal), `ctx`
- Mutated arguments: `trace`
- Writes ctx: —
- Reads ctx: —

Calls each template in "chain", in order, passing `ctx` directly — the
dispatcher for a specific library's "integration" templates.

Interface:
- Params (dict): { "chain": <list of fully-qualified template names>,
  "ctx": <the ctx dict>,
  "trace": <optional
  caller-owned dict> }
- Returns: nothing (each integration mutates `ctx` in place).

Implementation notes:
- Flat loop, not recursive: an integration receives plain `ctx` and does
  NOT call back into this template itself. A pre/post ("onion") need is
  met by splitting the integration into separate chain entries instead.
- `ctx` is a shared, mutate-in-place accumulator (same discipline as
  `$diag`) — never rebuilt or copied here.
- Chain entry names are the caller's own naming — crdkit never needs
  to know another chart's convention.
- With `trace`, appends to `trace.stages` (created when missing):
  `{entry: "", ctx}` before the first entry, then `{entry: <template
  name>, ctx}` after each — a snapshot via
  crdkit.snapshotCtx.internal. No `trace` → no snapshot, no cost.

### crdkit.listExtend

- Mutated arguments: `0`
- Writes ctx: —

Same as crdkit.dictMerge, but the final path segment is ensured to be a
LIST, and "value" is appended via `concat`.

Interface:
- Params (list): [model, key1, ..., keyN, value] (N >= 1, value is a
  list)
- Returns: nothing (mutates $model in place).

Implementation notes:
- No zero-key case (unlike dictMerge) — `ctx.model` is always a dict,

  place, so the final step needs an explicit `set` back onto the
  second-to-last level — unlike dictMerge's final step, which mutates
  the target map in place via `index`.

<a id="crdkit.render"></a>

### crdkit.render

- Scope: public
- File: `_render.tpl`
- Called by: —
- Calls: [crdkit.diag.error](#crdkit.diag.error), [crdkit.diag.lines](#crdkit.diag.lines), [crdkit.diag.warning](#crdkit.diag.warning), [crdkit.integrations.chain](#crdkit.integrations.chain), [crdkit.noParentTarget](#crdkit.noParentTarget), [crdkit.reservedKeys.internal](#crdkit.reservedKeys.internal), [crdkit.substituteValue.internal](#crdkit.substituteValue.internal), [crdkit.tokens.merge.internal](#crdkit.tokens.merge.internal)
- Mutated arguments: —
- Writes ctx: `ctx`
- Reads ctx: `ctx.diag`

The engine's entry point. Product-specific input (tokens, chain,
taxonomy) is supplied by the caller's own thin wrapper.

Interface:
- Params (dict):
  - context: consumer's root $ (never nested under .Values.<name>.*)
  - tokens: raw consumer token declarations (may include target-keyed
    dicts)
  - target: opaque string, whatever granularity the caller's taxonomy
    uses
  - system: raw locked-token declarations (always wins over consumer
    tokens — see crdkit.tokens.merge.internal)
  - defaults: raw default-token declarations (consumer may override)
  - parentTargetTemplate: fully-qualified template name implementing
    the caller's target-escalation taxonomy — optional, defaults to
    crdkit.noParentTarget (no escalation)
  - chain: ordered list of fully-qualified integration template names
    (called in list order) — the ONLY thing that builds ctx.model
  - tokenAnnotations: optional list of token annotation names supplied
    by the library (metadata on token declarations, e.g. an owning
    service). Each becomes a reserved key (never a target entry) on token
    declarations; crdkit stores them but never interprets or
    resolves them. A name equal to a crdkit-internal key, "match" or
    "default" records an ERROR and is ignored.

    with empty ones); crdkit only transports the seeded entries and
    appends new diagnostics as they arise, then emits them all

    runs — library-owned data for its integrations (e.g. normalized
    input); crdkit never reads it. A key equal to a crdkit ctx key
    records an ERROR and is ignored.

  `# ERROR:`/`# WARNING:`/`# INFO:` comment lines.

- Pipeline: merge tokens -> build empty ctx.model -> run the chain (the
  ONLY step that populates ctx.model) -> one substitution pass over the
  whole model -> scan for unresolved "@word@" markers (possible typos)
  -> replace "@AT@" with "@" -> emit `{{ model | toYaml }}`, then the diagnostics.
- ctx carries: root, diag, model, tokens, target, parentTargetTemplate,
  reservedKeys (list) and gen (int, starts at 0; bumped by
  crdkit.token.add / crdkit.token.underlay to invalidate resolution
  caches), plus every accepted "state" key.
- Never reads `context.Values` itself, and has no opinion on
  apiVersion/kind/labels/spec — entirely the chain's responsibility via
  crdkit.dictMerge/listExtend/ensureDictKey.
- No proactive "target is required" check — an unset target is only
  diagnosed lazily, if something resolves against it and the walk
  finds nothing.

<a id="crdkit.token.add"></a>

### crdkit.token.add

- Scope: public
- File: `_tokens.tpl`
- Called by: —
- Calls: [crdkit.annotationKey.internal](#crdkit.annotationKey.internal), [crdkit.diag.error](#crdkit.diag.error)
- Mutated arguments: `0`
- Writes ctx: —
- Reads ctx: —

Injects one derived token into a live tokens map — the crdkit.token.add
counterpart to crdkit.dictMerge/listExtend for ctx.model.

Interface:
- Params (list): [ctx, name, value, annotations?, target?]
  - ctx: dict with "tokens"/"diag"/"target"/"gen" keys
  - name: token name to add
  - value: raw value for this exact target (may contain "@ref@"
    markers, or be a structure — resolved lazily like any other value)
  - annotations: dict of annotation key-value pairs, optional — merged
    over existing annotations (a key present in both uses the new value;
    missing keys are inherited). Non-dict non-nil values record an ERROR
    but do not prevent the value from being stored. crdkit.token.add
    callers are trusted, first-party library code (no annotation values
    are validated).
  - target: exact target string "value" applies to — optional, defaults
    to ctx.target
- Returns: nothing (mutates ctx.tokens in place, bumps ctx.gen).

Implementation notes:
- Stores "value" as a dedicated attribute (literal key = target),
  merged into the token's existing entries — NOT resolved at add-time,
  so a value can reference a token another integration adds later in
  the chain.
- A repeat call for an existing name MERGES: new target → new key;
  same target → overwrite. Annotations are merged (new keys and
  overwrites present in both). The cache keys (_value, _gen) are dropped
  on write; _generated (see crdkit.token.underlay) is kept — an entry
  added here for a target beats the generated value for that target.
- Bumps ctx.gen to invalidate resolution caches — resolveEntry.internal
  checks _gen against the current generation to detect stale cache.
- Skips the reserved-name collision check
  (crdkit.tokens.merge.internal's) — that protects against untrusted
  consumer input; crdkit.token.add callers are trusted, first-party
  code.
